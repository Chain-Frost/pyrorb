## Boundary and source/policy status

The new `runoff_routing.monte_carlo_plan` API makes no routing calls, uses no mutable/global pseudorandom state and does not fabricate an effective hydrograph. Current `python-cmd/cmd-6.44` remains the temporary execution default; this sampler has no engine selection and is independently reusable with the intended later `python` engine.

This change intentionally supplies **no purported RORBwin empirical-loss CDF, native RNG, automatic TP probability band edges, joint loss dependence or engineering-approved rainfall interpolation**. The generic source-supplied inverse empirical loss table and explicitly named linear-in-AEP interpolation are provisional numerical controls. Scope #145 must review/adopt the versioned sampling/dependence and depth-interpolation rules before an accepted real-model MC workflow is enabled. The existing BoM/ARR source readers are reused through `ifd_from_bom` and `ifd_from_arr` (not reimplemented); EY and ARI are not silently mapped to AEP. The `source_id`/SHA-256 inputs must be bound to the verified original source bytes by the caller. `ifd_from_bom` requires depth in mm and exact duration; no implicit intensity conversion.

## Version 1 schema and handshake

The immutable plan manifest is JSON. A plan records `schema_version=1`, full `spec`, `plan_id`, `population_id`, optional `parent_plan_id` and `domain`. The `spec` records the explicit `policy` ID/version/status, scenario, duration (minutes), source SHA-256 map (`ifd`, `temporal_patterns`, optional `initial_loss`), RNG algorithm/derivation/root seed, strata, IFD depth table/interpolation, conditionally eligible TP `EventID`/source order/selection probabilities, storm IL mode, fixed parameters with units, ARF/preburst/joint policy IDs and the within-stratum transform. Every stratum stores exact AEP-fraction bounds, probability mass and sample count. The `domain` records modelled interior mass and both missing tails; it is never implicitly rescaled to probability one.

Sample records are UTF-8 NDJSON with `plan_id`, `sample_id`, stratum/index, scenario/duration, selected annual-exceedance **fraction**, `gross_ifd_depth_mm`, TP bin/original `EventID`/source order, primitive loss/TP uniforms, source-inverted storm IL ratio/millimetres and `event_probability_weight`. Storm IL is **storm** (pre-preburst) initial loss; applying source-specific ARF, preburst, storm hyetograph construction and routing is exclusively #149's responsibility. A manifest and record together provide the effective B-stage draw without an RNG call. Results and flow-frequency quantiles are not stored in the plan.

AEP is rainfall exceedance probability `p` in (0, 1], *not percent*, EY or ARI. Strata are contiguous disjoint `[lower,upper)` ranges (the final upper bound is closed for lookup); draws use a SHA-256-keyed open-interval 53-bit uniform in cumulative AEP probability mass: `p = lower + (upper-lower)*U`. Normal-coordinate bins can be constructed with `normal_coordinate_strata`, but a Normal coordinate does **not** mean rainfall depth is Normally distributed. Each original eligible TP member has an explicit positive probability summing to one within its conditional bin. Selection chooses the first cumulative weight **strictly greater** than its uniform; a value exactly equal to an internal boundary selects the following member. Empirical loss maps an explicitly source-identified nonexceedance-probability quantile table to a median-scaled **storm** IL; no default CDF is inferred.

The RNG profile is `sha256-counter53-v1`, derivation `sha256-utf8-zero-separated-v1`. Its inputs are algorithm, derivation, root integer seed, population digest, logical sample ID and purpose (`rainfall_aep`, `conditional_temporal_pattern`, `storm_initial_loss`), joined with zero bytes before SHA-256. The high 53 bits of the first eight digest bytes, mapped to their open-cell midpoint `(2*k+1)/2**54`, define each uniform. Same-source/seed runs are independent of chunk order, worker scheduling and global `random` state. **Same integer seed in RORBwin and Python does not imply equal native draws.** SHA-256 is used for reproducibility, not a claim that a given sampled parameter distribution is correct.

`population_id` hashes the canonical numerical spec **excluding only per-stratum sample counts**; `plan_id` hashes the complete numerical spec including those counts. The optional parent pointer records provenance but is excluded from the computational identity; an extension and a directly generated identical larger allocation therefore share `plan_id`. Sample IDs contain population digest, source stratum ID and within-stratum ordinal, never the revision hash. Increasing a stratum from `n_h` to `n'_h` leaves old logical IDs/primitive draws unchanged while all records for that stratum receive **new** `w_h/n'_h` weights. An old revision's records cannot be read as a new revision; #149 must reuse prior event computations by stable logical IDs and **reaggregate all weights** under the latest immutable plan.

`write_sample_plan` writes a no-overwrite `.plan.json` and streaming `.samples.jsonl` pair. `iter_stratum_samples` supports arbitrary finite chunks, `iter_saved_sample_records` streams validated replay (O(n) sample-index identities, not O(n) hydrographs), and `read_sample_records` is the bounded convenience reader for small plans. A complete reader rejects absent records, invalid positive-weight members, duplicates, source-derived numerical changes, incompatible plan/weight/revision IDs and malformed JSON. The record's `plan_id` must match the complete current revision; event result rows must separately bind that plan and engine identity.

## Test controls and outstanding acceptance

Controls cover strict IFD support and inversion direction, empirical median/scale, TP membership and edges, unequally weighted strata, unmodelled mass, original IDs, explicit replay without RNG, deterministic reorder/chunk, seed change, full-plan extension/weight revision, fixed versus stochastic losses, malformed CDF/probability, duplicate/missing rows and immutable no-overwrite output. Source-only isolated testing is **not** the repository's installed-wheel equivalence receipt.
