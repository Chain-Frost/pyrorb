## Meaning of the columns

- **Native evidence** describes the *actual retained CMD 6.44 reference*, not universal RORB support. Original native binaries are not distributed; ordinary tests use original outputs.
- **`python-cmd`** describes the bounded implementation proposed in draft #79. `implemented, unqualified` is not a native-equivalence pass; other rows remain explicit exclusions.
- **`python`** describes the currently supported default S1/S2 typed subset, not an independently validated engineering-accuracy claim.
- The selected `rorb-cmd` adapter is an **explicit, optional, locally configured native executable**; it cannot substitute for a missing feature in either Python engine.
- Any feature without a native-observation/profile-qualified validation is `incomplete`, not automatically `unsupported` forever. An expected rejection is not a computed hydrograph pass.

The two zero-flow cases `fig67-zero` and `wheel-zero` each have 301 stored zero-discharge samples; all 48 nonzero candidate hydrographs have a **unique exact stored maximum**. Thus the 50-case candidate snapshots contain no nonzero exact-peak ties that can establish a general native selection rule. These are **candidate** arrays, not direct observations of native internal ties.

Likewise, 48 of those 50 retained candidate outputs have a nonzero difference between the inclusive reported-volume statistic and the trapezoidal physical-horizon statistic because `dt*(Q0+QN)/2` is nonzero. This derived identity says **nothing by itself** about source/outlet/storage conservation.

## Remaining named native gaps

The eleven CMD records are three **negative/failed controls** (`failure-invalid-code`, `failure-truncated-storm`, `invalid-catchment`), one **incomplete raw output** (`fig67-code11`) and seven **captured but unreviewed** inputs (`failure-m-above-one`, `failure-m-below-one`, `failure-negative-reach-repeat`, `failure-negative-reach`, `failure-zero-reach`, `fig67-ilroc`, `fig67-kc5-m1`). The ten RORBwin 6.52 entries are deferred explicitly under `native-gaps`. Every ID remains in the single public register; **none is erased from the denominator** by this inventory.

## Acceptance order — do not close #5 based on this inventory

1. Use #75's fresh, installed public `python-cmd` to establish an **actual input admission/output comparison ledger** against the 50 public original CMD references, with every unexecuted or unsupported case retained.
2. Qualify missing in-scope CMD cases in small feature slices, using the same register and distinct engine-specific policies. Do not label private candidate source/wheel results as acceptance of a different public integration build.
3. For peak/ties, request directly bound native exact states when the retained original output lacks them; an authored linear plateau does not qualify every nonlinear tie.
4. For physical accuracy, keep native reported volume, physical trapezoid, discrete stored-state defects and project engineering tolerances separate. Original sample-zero/prefix S and pre-addition flux observations and a prospective engineering budget are absent for broad acceptance. The analytic `2^-12 m³` budget reviewed privately is **only conditional on its separate manufactured linear control** and has not been applied to nonlinear cases.
5. Obtain independent review of this actual capability inventory and the final in-scope CMD feature list. Only then can the full-engine replacement gate be considered.
